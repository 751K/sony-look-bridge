# 视频 LUT

本页说明 α7 V 视频 LUT 如何把照片 Creative Look 用于 S-Log3 素材，以及标定方法与验证结果。下载与使用见[视频 LUT 使用说明](../profiles/video/README.md)，生成命令见[开发与发布](development.md#生成视频-lut)。

## 原理

照片外观链的输入是白平衡后的相机 RGB（[处理管线](pipeline.md)）。视频 LUT 先把 S-Log3 素材换算成同样的相机 RGB，再送入照片外观链：

```text
S-Log3 / S-Gamut3(.Cine)
  → 线性 ACES2065-1（AP0）
  → 实测矩阵：线性 S-Gamut3.Cine → 白平衡后的相机 RGB（按色温版本选用）
  → 曝光调整 → 负值向灰轴收缩 → 高光压缩 → Sony 原生刻度
  → 照片外观链：SSCS → LinearMatrix16 → MainGamma → RGB2YCC → … → YGamma
  → sRGB 解码 → Gamma 2.4 编码
```

S-Log3 反函数、色域转换和 CAT02 白点适配采用 [Sony 的 ACES 转换代码](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/CSC.Sony.SLog3_SGamut3Cine_to_ACES.ctl)；[Sony 的说明](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/README.md)分别列出了两种输入色域。经 ACES 中转与直接做色域转换在数学上等价。

线性 S-Gamut3.Cine 到相机 RGB 的矩阵由同一机位下照片与视频的实测颜色得到，并按灰轴归一化。曝光补偿后，若相机 RGB 的最大通道超过 0.9，三个通道按同一比例压缩高光。12 种外观各生成 S-Gamut3 与 S-Gamut3.Cine 两种输入版本，输出为 Rec.709 / Gamma 2.4。

## 色温版本

S-Gamut3.Cine 与相机 RGB 之间的关系随白平衡变化，照片外观本身也随白平衡在暖光与日光两种状态之间过渡（[照片配置](photo.md#日光版暖光版与自动版)）。LUT 无法得知素材的白平衡，因此分为三套：

| 版本 | 文件名中的外观代号 | 矩阵来源 | 外观状态（混合权重） | 适用的拍摄白平衡 |
| --- | --- | --- | --- | --- |
| 日光 | `ST` | 6500K 色卡 | `0 1024 0 0` | 约 5000K 以上 |
| 4200K | `ST-4200K` | 4200K 色卡 | `644 380 0 0`，即相机在该光源下的权重 | 约 4300K 至 5000K |
| 暖光 | `ST-Warm` | 2600K 色卡 | `1024 0 0 0` | 约 4300K 以下 |

相机照片在 4100K 及以下完全采用暖光状态，5400K 及以上完全采用日光状态（[处理管线 §4.3](pipeline.md)）。适用范围取相邻两个版本之间的中点，均指相机的白平衡设定值。

## 色卡标定

三套矩阵取自 ColorChecker Passport Photo 2 的实拍。COB 灯加柔光箱分别设为 2600K、4200K 和 6500K；每种光源下以自定义白平衡拍摄 RAW 照片（ISO 100、1/15 秒、f/5.6）和 S-Log3 / S-Gamut3.Cine 视频（ISO 800），机位不变。照片端取 ColorChecker Classic 页的 24 个色块和另一页的 26 个色块（8 个彩色、10 个白平衡色块、8 级灰阶），视频端取前 1 秒的帧平均，拟合灰轴归一化的矩阵 `N`。结果见 `video/calibration/A7M5_SGamut3Cine_chart_*.json`：

```text
2600K: [[ 0.9669  0.0233  0.0098] [ 0.0574  1.0490 -0.1064] [-0.0406  0.3570  0.6835]]
4200K: [[ 0.9092  0.0747  0.0161] [ 0.0083  0.9248  0.0669] [-0.0196  0.1795  0.8401]]
6500K: [[ 0.8332  0.1339  0.0329] [-0.0078  0.8739  0.1339] [-0.0223  0.1900  0.8323]]
```

以一页拟合、另一页检验，十种彩色外观与同一光源下相机 HEIF 的 ΔE2000 平均值如下。照片与视频的曝光和白平衡已在中性色块上对齐；"屏幕色块矩阵"一列是此前使用的矩阵（见[曝光刻度](#曝光刻度)）。

| 光源 | 照片按拍摄参数解码 | 屏幕色块矩阵、日光状态 | Classic 页拟合 → 另一页检验 | 另一页拟合 → Classic 页检验 |
| --- | --- | --- | --- | --- |
| 2600K | 0.20–0.32 | 1.29–2.05 | 0.58–0.92 | 0.96–1.12 |
| 4200K | 0.23–0.44 | 1.40–1.66 | 0.49–0.79 | 0.70–0.95 |
| 6500K | 0.22–0.58 | 1.12–1.44 | 0.61–0.92 | 0.82–1.33 |

用两页共同拟合的矩阵交叉使用时，矩阵与光源一致为 0.70–0.78，相差一档为 1.36–3.07，2600K 与 6500K 互换为 3.58–3.95，可见这一关系随白平衡变化。经 LUT 的完整渲染路径，并在 LUT 之前做中性色平衡后，各版本在对应光源下为 0.60–1.07，屏幕色块矩阵为 1.28–2.49。

## 随白平衡过渡

`.cube` 是固定的 RGB 映射，无法读取素材的白平衡。DaVinci Resolve 的 DCTL 同时加载一种外观的三套 LUT，按 White Balance 滑块混合输出：4100K 及以下为暖光版，4640K 为 4200K 版，5400K 及以上为日光版，各段之间按 mired 线性插值。

- 4640K 是 4200K 色卡光源下视频记录的白平衡。4100K 与 5400K 是照片外观完全进入暖光或日光状态的位置，由手动色温白平衡逐档拍摄测得。照片与视频使用相机同一套色温刻度，滑块应设为相机记录的白平衡。
- 中间锚点不能省略。在 4200K 色卡上，按相机权重直接混合暖光版与日光版为 1.90 ΔE2000，使用 4200K 版为 0.70；三点插值时若权重从 0.63 偏到 0.32，结果为 0.98。
- 相机的混合权重并不只取决于色温，同一色温下偏绿的光源权重不同，因此滑块可以按画面微调。

## 曝光刻度

LUT 还需要知道 S-Log3 的场景亮度对应照片端的哪个 Sony 原生值。这一刻度来自屏幕色块：标定工具生成一页 display-P3 色块，从同一画面的 RAW 和 S-Log3 视频中读取色块并拟合。

```bash
python3 video/sensor_calibration.py chart
python3 video/sensor_calibration.py fit PHOTO.ARW CLIP.MP4 --out sensor_matrix.json
```

色块页共 144 块：16 级灰阶、128 个不同亮度和饱和度的彩色块，四角为定位块。拍摄时固定机位，手动设置白平衡、光圈和快门，不改变屏幕亮度；在暗室中拍摄，关闭原彩显示、夜览和自动亮度，不使用 ND / VND，并略微失焦以避免摩尔纹。程序按四角定位块对齐，取每个色块中央 7×7 个采样点的中位数，剔除过曝和过暗的色块，再把拟合矩阵分解为 `s · diag(wb) · N`：`N` 是灰轴归一化后的颜色关系，`wb` 是两次拍摄之间的白平衡差异，`s` 是这一对照片与视频的曝光比例。

下表按记录的标称 ISO、快门和光圈，将四组配对换算到相同的拍摄条件：

| 配对 | 视频相对照片的进光量 | 换算后的 Sony 刻度 |
| --- | --- | --- |
| DSC06651 / C2688（色块页） | −0.30 档 | 5450 |
| DSC06651 / C2687（色块页） | +1.44 档 | 5239 |
| DSC06654 / C2689（夜景） | +1.32 档 | 4960 |
| DSC06654 / C2690（夜景） | −0.65 档 | 5175 |

四组的几何平均为 **5203**：S-Log3 场景线性值 1 对应 Sony 原生值 5203，0.18 对应约 937。四组刻度的极差为 0.14 档，标准差为 0.056 档。三个色卡标定文件都沿用 `sony_scale = 5203.2`。

屏幕色块也能拟合颜色矩阵（`video/calibration/A7M5_SGamut3Cine_sensor_matrix.json`，拟合相对误差平均 0.49%），此前的 LUT 曾使用它。但屏幕发光的光谱较窄，与反射物体差异较大，该矩阵在 6500K 色卡上仍有 1.1–1.4 ΔE2000 的偏差，因此现在只用屏幕色块确定曝光刻度。

## 验证

- **插值误差**：72 个 65³ LUT 相对直接计算的四面体插值误差 MAE 为 0.09–0.26、p99 为 0.38–2.35，单位为 8 位输出码值。灰阶检查要求各通道单调递增；Sepia 检查亮度，允许 1e-4 的舍入误差。`validation.json` 记录了用 `colour-science` 独立读回的结果，以及 ACES 矩阵和两种输入色域的对照。
- **色卡**：三种光源下的结果见[色卡标定](#色卡标定)。
- **夜景**：场景含 LED 和暖色路灯，白平衡 3000K，以低饱和颜色为主。曝光不足的夜景视频曾出现比照片更低的饱和度，低信号中的噪声和光晕可能是原因之一。夜景 C2689 经曝光补偿后，中位显示亮度为 0.0200，照片 ST 为 0.0196。
- **日光场景**：瀑布素材 C1620 按 +1⅔ 档补偿后，观感与相邻的 ST 照片接近。该组照片与视频的 VND 档位不同，只能用于方向检查。色彩丰富的自然日光场景尚未定量验证。

LUT 只是逐像素的颜色与影调变换。锐度、清晰度和 DRO 等空间处理不在 LUT 中，需要由宿主软件完成。
