# 视频 LUT

本页说明 α7 V 视频 LUT 如何把照片 Creative Look 用于 S-Log3 素材，以及标定方法与验证结果。下载与使用见[视频 LUT 使用说明](../profiles/video/README.md)，生成命令见[开发与发布](development.md#生成视频-lut)。

## 原理

照片外观链的输入是白平衡后的相机 RGB（[处理管线](pipeline.md)）。视频 LUT 先把 S-Log3 素材换算成同样的相机 RGB，再送入照片外观链：

```text
S-Log3 / S-Gamut3(.Cine)
  → 线性 ACES2065-1（AP0）
  → 实测矩阵：线性 S-Gamut3.Cine → 白平衡后的相机 RGB（按色温版本选用）
  → 曝光调整 → 负值向灰轴收缩 → 高光压缩 → Sony 原生刻度
  → 照片外观链：LinearMatrix16 → MainGamma → RGB2YCC → … → YGamma
  → sRGB 解码 → Gamma 2.4 编码
```

S-Log3 反函数、色域转换和 CAT02 白点适配采用 [Sony 的 ACES 转换代码](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/CSC.Sony.SLog3_SGamut3Cine_to_ACES.ctl)；[Sony 的说明](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/README.md)分别列出了两种输入色域。经 ACES 中转与直接做色域转换在数学上等价。

线性 S-Gamut3.Cine 到相机 RGB 的矩阵由同一机位下照片与视频的实测颜色得到，并按灰轴归一化。曝光补偿后，若相机 RGB 的最大通道超过 0.9，三个通道按同一比例压缩高光。外观链与照片配置相同，按相机直出不包含 SSCS 与 ChromaSuppress（见[照片配置](photo.md)）；正常曝光的色卡视频上，去掉这两步前后的整条路径误差均为 0.49 ΔE2000，差异只出现在接近饱和的亮色上。12 种外观各生成 S-Gamut3 与 S-Gamut3.Cine 两种输入版本，输出为 Rec.709 / Gamma 2.4。

## 色温版本

S-Gamut3.Cine 与相机 RGB 之间的关系随白平衡变化，照片外观本身也随白平衡在暖光与日光两种状态之间过渡（[照片配置](photo.md#日光版暖光版与自动版)）。LUT 无法得知素材的白平衡，因此按六个白平衡锚点各生成一套，文件名中的外观代号带锚点色温，如 `ST-4300K`：

| 版本 | 外观状态（混合权重） | 适用的拍摄白平衡 |
| --- | --- | --- |
| 2500K | `1024 0 0 0` | 约 2800K 以下 |
| 3100K | `1024 0 0 0` | 约 2800K 至 3600K |
| 4300K | `844 180 0 0` | 约 3600K 至 4600K |
| 4900K | `312 712 0 0` | 约 4600K 至 5100K |
| 5300K | `4 1020 0 0` | 约 5100K 至 6200K |
| 7500K | `0 1024 0 0` | 约 6200K 以上 |

每套使用在该白平衡下实测的矩阵，以及相机照片在该白平衡下的混合权重（[处理管线 §4.3](pipeline.md)）。适用范围取相邻两个锚点在 mired 上的中点，均指相机记录的白平衡。

## 色卡标定

矩阵取自 ColorChecker Passport Photo 2 的实拍。色卡与相机固定，只用一盏灯照明；通过遥控把视频与照片的白平衡同时设为 2500K 至 7500K 的色温，每 200K 一档，共 26 档。每档先录 2 秒 S-Log3 / S-Gamut3.Cine 视频（ISO 800），紧接着拍一张 RAW 照片（ISO 100、1/30 秒），使两者处于同一光线下。照片端与视频端各取 38 个色块：Classic 页 24 个、另一页的 7 个彩色块和 7 级灰阶；视频端取前 1 秒的帧平均，拟合灰轴归一化的矩阵 `N`。照片与视频之间的白平衡差异在各档均小于 0.5%，拟合相对误差平均为 0.6%–0.9%。

`N` 随白平衡连续变化，但不单调。以蓝通道对绿色的系数 `N[2,1]` 为例，2500K 时为 0.37，到 4300K 降至 0.08，4500K 至 5100K 之间回升到 0.24，之后缓慢降到 7500K 的 0.18。按 mired 在锚点之间线性插值矩阵时，各档与自身拟合矩阵的 ΔE2000 平均值（ST 日光状态，38 个色块）最大为：

| 锚点 | 最大 | 平均 |
| --- | --- | --- |
| 3 个（2500、4700、7500K） | 1.47 | 0.74 |
| 4 个（2500、4300、4900、7500K） | 0.76 | 0.48 |
| 5 个（2500、3100、4300、4900、7500K） | 0.54 | 0.43 |

LUT 采用这五个锚点，另加 5300K，使照片外观从暖光到日光的过渡也落在锚点上。六个锚点的矩阵见 `video/calibration/A7M5_SGamut3Cine_wb_*.json`：

```text
2500K: [ 1.0104 -0.0163  0.0059] [ 0.0734  1.0386 -0.1121] [-0.0314  0.3662  0.6653]
3100K: [ 0.9388  0.0692 -0.0079] [ 0.0203  1.0388 -0.0591] [-0.0440  0.2840  0.7600]
4300K: [ 0.9231  0.0556  0.0213] [-0.0031  0.9444  0.0587] [-0.0017  0.0839  0.9178]
4900K: [ 0.9451  0.0550 -0.0001] [ 0.0216  0.9165  0.0619] [-0.0297  0.2310  0.7987]
5300K: [ 0.9340  0.0653  0.0007] [ 0.0200  0.9071  0.0730] [-0.0306  0.2354  0.7952]
7500K: [ 0.8620  0.1113  0.0267] [-0.0034  0.8740  0.1294] [-0.0219  0.1815  0.8404]
```

v4.0.0 的三套矩阵（`A7M5_SGamut3Cine_chart_*.json`）分别在 COB 灯的 2600K、4200K、6500K 下以自定义白平衡拍摄，视频记录的白平衡为 2520K、4640K 与 7510K，仍保留在仓库中供对照。

## 随白平衡过渡

`.cube` 是固定的 RGB 映射，无法读取素材的白平衡。DaVinci Resolve 的 DCTL 同时加载一种外观的六套 LUT，按 White Balance 滑块在相邻两套之间按 mired 线性混合输出；2500K 以下使用 2500K 版，7500K 以上使用 7500K 版。照片与视频使用相机同一套色温刻度，滑块应设为相机记录的白平衡。

在 26 档色卡视频上模拟 DCTL 的完整路径，并与紧接着拍摄的相机 HEIF 比较（ST，38 个色块，每档按中灰对齐曝光），ΔE2000 平均值如下。26 档中只有 6 档用于标定，其余 20 档为独立检验：

| 白平衡 | 六个锚点 | v4.0.0（三套，锚点 3700K、4640K、5470K） |
| --- | --- | --- |
| 2500–2900K | 0.57–0.75 | 1.23–2.00 |
| 3100–4100K | 0.46–0.79 | 2.65–3.99 |
| 4300–5300K | 0.30–0.42 | 0.72–2.22 |
| 5500–7500K | 0.33–0.58 | 0.77–1.36 |
| 全部 | 平均 0.49，最大 0.79 | 平均 1.66，最大 3.99 |

## 曝光刻度

LUT 还需要知道 S-Log3 的场景亮度对应照片端的哪个 Sony 原生值。这一刻度来自屏幕色块：标定工具生成一页 display-P3 色块，从同一画面的 RAW 和 S-Log3 视频中读取色块并拟合。

```bash
python3 video/sensor_calibration.py chart
python3 video/sensor_calibration.py fit PHOTO.ARW CLIP.MP4 --out sensor_matrix.json
```

色块页共 144 块：16 级灰阶、128 个不同亮度和饱和度的彩色块，四角为定位块。拍摄时固定机位，手动设置白平衡、光圈和快门，不改变屏幕亮度；在暗室中拍摄，关闭原彩显示、夜览和自动亮度，不使用 ND / VND，并略微失焦以避免摩尔纹。程序按四角定位块对齐，取每个色块中央 7×7 个采样点的中位数，剔除过曝和过暗的色块，再把拟合矩阵分解为 `s · diag(wb) · N`：`N` 是灰轴归一化后的颜色关系，`wb` 是两次拍摄之间的白平衡差异，`s` 是这一对照片与视频的曝光比例。

下表按记录的标称 ISO、快门和光圈，将四组配对换算到相同的拍摄条件：

| 配对 | 视频相对照片的进光量 | 换算后的 Sony 刻度 |
| --- | --- | --- |
| DSC06651 / C2688（色块页） | −0.30 档 | 5450 |
| DSC06651 / C2687（色块页） | +1.44 档 | 5239 |
| DSC06654 / C2689（夜景） | +1.32 档 | 4960 |
| DSC06654 / C2690（夜景） | −0.65 档 | 5175 |

四组的几何平均为 **5203**：S-Log3 场景线性值 1 对应 Sony 原生值 5203，0.18 对应约 937。四组刻度的极差为 0.14 档，标准差为 0.056 档。各标定文件都沿用 `sony_scale = 5203.2`。

屏幕色块也能拟合颜色矩阵（`video/calibration/A7M5_SGamut3Cine_sensor_matrix.json`，拟合相对误差平均 0.49%），此前的 LUT 曾使用它。但屏幕发光的光谱较窄，与反射物体差异较大，该矩阵在 6500K 色卡上仍有 1.1–1.4 ΔE2000 的偏差，因此现在只用屏幕色块确定曝光刻度。

## 验证

- **插值误差**：144 个 65³ LUT 相对直接计算的四面体插值误差 MAE 为 0.10–0.26、p99 为 0.35–2.36，单位为 8 位输出码值。灰阶检查要求各通道单调递增；Sepia 检查亮度，允许 1e-4 的舍入误差。`validation.json` 记录了用 `colour-science` 独立读回的结果，以及 ACES 矩阵和两种输入色域的对照。
- **色卡**：26 档白平衡下的结果见[随白平衡过渡](#随白平衡过渡)。
- **S-Gamut3 输入**：矩阵只在 S-Gamut3.Cine 下标定，S-Gamut3 版本经固定的色域换算得到。同一色卡改用 S-Gamut3 在 2500K 至 7500K 每 1000K 各录一段并配拍照片，经六套 LUT 的完整路径与相机 HEIF 的 ΔE2000 平均值为 0.41–0.82；直接在这些 S-Gamut3 视频上拟合矩阵为 0.39–0.80，v4.0.0 为 0.79–3.54。
- **ISO**：标定都在 ISO 800 下完成。4300K 下以 ISO 800 至 12800 各录一段，快门随 ISO 加快以保持曝光，矩阵与 ISO 800 的差异不超过 0.005；跨过第二档原生 ISO 8000 时也没有变化，2500K 与 7500K 下的 6400 与 8000 同样一致。六套 LUT 的完整路径为 0.50–0.73，随 ISO 略有上升，来自暗部色块的噪声。
- **曝光刻度**：同一组配对的视频为 ISO 800、1/125 秒，照片为 ISO 100、1/30 秒，按标称值换算后 Sony 刻度为 5211，与屏幕色块得到的 5203 相差 0.002 档；ISO 1600 至 12800 为 5236–5335，最多相差 0.036 档。
- **夜景**：场景含 LED 和暖色路灯，白平衡 3000K，以低饱和颜色为主。曝光不足的夜景视频曾出现比照片更低的饱和度，低信号中的噪声和光晕可能是原因之一。夜景 C2689 经曝光补偿后，中位显示亮度为 0.0200，照片 ST 为 0.0196。
- **日光场景**：瀑布素材 C1620 按 +1⅔ 档补偿后，观感与相邻的 ST 照片接近。该组照片与视频的 VND 档位不同，只能用于方向检查。色彩丰富的自然日光场景尚未定量验证。

LUT 只是逐像素的颜色与影调变换。锐度、清晰度和 DRO 等空间处理不在 LUT 中，需要由宿主软件完成。
