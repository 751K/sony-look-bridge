# S-Log3 Creative Look 视频 LUT

本 LUT 的目标是使 S-Log3 视频的输出模仿 α7 V 照片 Creative Look 的色调。它覆盖全部 12 种外观（ST、PT、NT、VV、VV2、FL、IN、SH、BW、Sepia、FL2、FL3），输入为 S-Log3 / S-Gamut3 或 S-Gamut3.Cine，输出为 Rec.709 / Gamma 2.4，网格为 65³。文件与用法见[视频 LUT 说明](../profiles/video/README.md)，随仓库 v2.0.0 发布。

## 中灰的输入与输出

本 LUT 的中灰位置与常规 S-Log3 LUT 不同。

| | 本 LUT | 常规 S-Log3 LUT（如索尼 LC-709TypeA） |
| --- | --- | --- |
| 设计的拍摄曝光 | 测光 +1⅔ 档（相机显示 +1.7） | 测光 0 |
| 18% 灰的 S-Log3 输入码值 | 547 / 1023 | 420 / 1023 |
| 18% 灰的 Rec.709 输出码值 | 0.607 | 约 0.40 |

输入端按 +1⅔ 档设计，因为这是 S-Log3 常用的拍摄曝光，可以降低暗部噪声。素材的实际曝光不同时，应在 LUT 之前用曝光调整补偿。

输出端的中灰按照片的影调放置，因此比常规视频 LUT 亮，高光的余量相应较少：ST 的白点约在中灰以上 3 档。这一取舍使视频与照片的亮度一致；若需要常规视频的中灰位置，应另行生成相应版本。

## 原理

照片外观链（见[照片管线](pipeline.md)：LM16 → MainGamma → RGB2YCC → … → YGamma）的输入是白平衡后的相机 RGB。S-Log3 视频与照片来自同一传感器，S-Gamut3.Cine 由机内矩阵从传感器 RGB 计算得到。测得该矩阵后，即可将视频还原为相机 RGB，并送入与照片相同的外观链：

```text
S-Log3 / S-Gamut3(.Cine)
  → ACES2065-1（AP0，线性，CAT02 D65→D60）
  → 实测矩阵 N：S-Gamut3.Cine 线性 → 白平衡后的相机 RGB
  → 负值按 Sony 色相亮度向灰轴收缩，曝光，高光压缩，实测 Sony 刻度
  → 照片外观链 F_L（SSCS、LM16、MainGamma、RGB2YCC、ChromaSuppress、YGamma、褪色）
  → sRGB 解码 → Gamma 2.4 编码
```

输入端的 Log 解码与色域转换和 [Sony 提供给 ACES 的 CTL](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/CSC.Sony.SLog3_SGamut3Cine_to_ACES.ctl) 一致，两种视频色域使用[统一输入转换](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/main/sony/README.md)。经 ACES 接入矩阵与直接进行色域转换在数学上等价。

## 采用实测矩阵的原因

照片外观链的 LM16 一级接收相机 RGB，其饱和度低于 S-Gamut3.Cine。若以色度准确的线性 sRGB 代替相机 RGB 送入外观链，高饱和区域的色度将被重复提高。因此本 LUT 以实测矩阵还原相机 RGB，而不采用色度准确的中间空间。

以 Adobe DCP 的 ForwardMatrix 推算该矩阵，结果的方向相反（饱和度更高）。ForwardMatrix 只是 Adobe 色彩模型的一部分，不宜单独用于此处的衔接。

## 传感器矩阵的测量

`video/sensor_calibration.py` 分为两步：

```sh
python3 video/sensor_calibration.py chart                  # 生成全屏色块页 video/calibration_chart.html
python3 video/sensor_calibration.py fit PHOTO.ARW CLIP.MP4 --out sensor_matrix.json
```

色块页包含 144 个 display-P3 色块：第一行为 16 级灰阶，其余 8 行各含 16 个色相，按不同饱和度和亮度分布；四角为白色定位块。屏幕光谱为窄带光谱，不适合与标准色值比对；此处比较的是同一传感器在两种模式下的读数，不受此影响。

拍摄条件：使用三脚架，不加 ND 或 VND（VND 由两片偏振片组成，档位改变时偏振和偏色随之改变）；在暗室中拍摄；关闭原彩显示、夜览和自动亮度；略微失焦以避免摩尔纹；照片与视频使用相同的手动白平衡、光圈和快门。

拟合过程：照片端以 `front_end_sony` 取得白平衡后的相机 RGB；视频端取前 1 秒的帧平均并解码 S-Log3。自动定位四角白块后，以单应变换在每个色块中央取 7×7 个采样点的中位数，剔除过曝和过暗的色块，再以相对误差加权进行最小二乘拟合。所得矩阵分解为 `s · diag(wb) · N`：

- `N` 满足 `N·1 = 1`，表示两种模式之间的颜色关系，LUT 使用该矩阵；
- `wb` 为两次拍摄之间的白平衡差异，不进入 LUT；
- `s` 为曝光关系。

若强制灰色映射为灰色，而两次拍摄的白平衡实际不一致，拟合误差将由 0.5% 升至 3–7%。因此白平衡差异须先行分离。

## 测量结果

色块图数据来自 DSC06651（ISO 100，1/13 秒，f/4），以及同一机位下的 C2688（S-Log3，ISO 800，1/128 秒，f/4，6000K）和 C2687（ISO 2500，1/120 秒，f/4，5000K）。视频的拍摄参数读自 XAVC 文件的 rtmd 元数据流（0x8000 光圈、0x8109 快门、0x810b ISO、0x810e 色温）。结果保存于 [`video/calibration/A7M5_SGamut3Cine_sensor_matrix.json`](../video/calibration/A7M5_SGamut3Cine_sensor_matrix.json)。

| | C2687（矩阵来源） | C2688 |
| --- | --- | --- |
| 可用色块 | 142 / 144 | 142 / 144 |
| 相对误差 均值 / p95 | 0.49% / 1.3% | 0.82% / 2.9% |

```text
N (S-Gamut3.Cine → 相机 RGB) =
[[ 0.9458  0.0562 -0.0020]
 [ 0.0231  0.9133  0.0635]
 [-0.0284  0.2483  0.7801]]
```

两段视频的白平衡分别为 5000K 和 6000K，两次拟合得到的白平衡差异因而不同；颜色矩阵 `N` 不受影响。

## 曝光关系

曝光关系按标称 ISO、快门和光圈换算至同一 ISO，不依赖测光表在具体画面上的读数。照片 ISO 与 S-Log3 ISO 均以测光 0 为基准，因此同一 ISO 下的比例即两者均按测光 0 拍摄时的比例。共使用四组配对：

| 配对 | 视频相对照片的进光量 | 换算后的刻度 |
| --- | --- | --- |
| DSC06651 / C2688（色块图） | −0.30 档 | 5450 |
| DSC06651 / C2687（色块图） | +1.44 档 | 5239 |
| DSC06654 / C2689（夜景，ISO 12800 / 32000） | +1.32 档 | 4960 |
| DSC06654 / C2690（夜景） | −0.65 档 | 5175 |

四组的几何平均为 5203，即 S-Log3 场景值 1 对应照片相机原生值 5203，18% 灰对应 937。最大值与最小值相差 0.14 档，标准差为 0.056 档。同批两段视频的实测亮度差与按拍摄参数推算的差相差 0.05–0.06 档（色块图 1.79 档对 1.74 档，夜景 2.03 档对 1.97 档），表明 S-Log3 解码在此范围内保持线性。

若假设两次拍摄均处于测光 0，估算值为 6707，偏高 0.37 档；其原因是 C2688 的实际进光量比照片少 0.30 档。

LUT 以 5203 为刻度生成，并在输入端减去 1.667 档。高光压缩自场景值 0.9 开始，三个通道按同一比例缩放。夜景验证：C2689 比照片多进光 1.32 档，补偿后渲染的中位显示亮度为 0.0200，照片 ST 为 0.0196。

## 生成与验证

```sh
python3 video/video_look.py ARW --write --eval --out DIR
python3 video/validate_luts.py DIR
python3 -m unittest discover -s video -p 'test_*.py' -v
```

`ARW` 仅提供 Creative Look 的参数表，任一 α7 V 的 ARW 均可。生成器默认读取 `video/calibration/` 中的矩阵与刻度，生成全部 12 种外观，并在输入端减去 1.667 档；`--exposure` 可生成其他拍摄曝光的版本，`--sensor-matrix` 和 `--sony-scale` 可替换标定结果。

65³ LUT 相对直接计算的四面体插值误差：12 种外观的 MAE 为 0.10–0.23 个 8 位码值，p99 为 0.39–2.12，其中饱和度最高的 VV 最大。灰阶检查要求各通道单调递增；Sepia 沿灰阶改变色调，单个通道不必单调，因此改为检查显示亮度，允许 1e-4 以内的整数舍入误差。`validate_luts.py` 以 colour-science 独立检查 ACES 矩阵（误差小于 1e-10）、读回插值（误差约为 3e-16）以及两种输入色域的一致性（MAE 约 0.1 个 8 位码值）。单元测试覆盖 Log 码值、白点适配、色域等价性、高光压缩、`.cube` 写出顺序，以及从透视变形的合成色块图中反求已知矩阵和白平衡。

## 局限

- 矩阵在显示器光源（约 6500K）下测得。索尼可能按色温切换机内视频矩阵；日光素材预计适用，钨丝灯等低色温光源尚未核对。
- 曝光关系以相机的 ISO 标称值为依据，在两种场景、ISO 100–32000 范围内一致（标准差 0.056 档）。实际拍摄中，测光表在不同画面上的读数仍可能相差数十分之一档。
- 颜色矩阵在夜景（LED 与暖色路灯混合，3000K 白平衡）中未见异常，但该场景以低饱和色为主，不足以单独检验矩阵。色彩丰富的日间场景尚未验证。
- 曝光不足的 S-Log3 素材（例如夜景少给 2 档曝光）饱和度明显低于照片。其原因是噪声底和光晕在低信号中占比增大，LUT 无法补偿。
- LUT 仅包含逐像素的色彩与影调。照片外观中的锐度、清晰度、DRO 等空间处理不在其中。
- 土耳其瀑布素材（C1620）按 +1⅔ 档补偿渲染后，色彩与相邻照片的 ST 观感一致。该组照片使用了 VND，档位与视频不同，因此仅用于检查方向，不作为定量标定。
